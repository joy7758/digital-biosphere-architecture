# FDO Forum Short Post

We have recently tightened the public entry structure of the Digital Biosphere Architecture.

The current architecture is now presented as a standard entry matrix across five layers:

- POP as the persona object entry
- AIP as the interaction protocol entry
- Token Governor as the runtime governance entry
- MVK as the execution integrity verification entry
- ARO-Audit as the audit evidence profile entry

We are not presenting this as a finalized FDO standard.

Instead, we are asking whether these should be read as candidate FDO-facing entry artifacts for autonomous AI systems.

In particular, we think the most mature discussion points are:

- POP as a candidate persona object profile
- AIP as a candidate interaction semantics profile
- ARO-Audit as a candidate audit evidence profile
- MVK as a conformance and verification surface

We would especially welcome feedback on:
- profile boundary clarity
- terminology alignment
- whether audit evidence should be treated as a profile candidate or another architectural category
