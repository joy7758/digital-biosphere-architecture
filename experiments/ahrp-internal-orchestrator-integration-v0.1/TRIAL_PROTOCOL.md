# TRIAL_PROTOCOL — AHRP Internal Orchestrator Integration Trial v0.1

AHRP 内部编排器集成试验 v0.1。Trial ID:
`ahrp-internal-orchestrator-integration-v0.1`

## 1. Question

> Can a programmatic orchestrator integrate the frozen AHRP v0.1 query
> interface and bind returned history to auditable delegation decisions?
>
> 程序化编排器能否集成冻结的 AHRP v0.1 查询接口，并将返回的历史记录
> 绑定到可审计的委派决策？

本试验允许回答：

```text
AHRP_QUERY_INTERFACE_INTEGRATED=true
HISTORY_BOUND_TO_DECISION_RECORD=true
PROGRAMMATIC_DECISION_CHANGED_BY_HISTORY=true
QUERY_FAILURE_FAIL_CLOSED=true
```

本试验不得回答：

```text
AGENT_VOLUNTARILY_ADOPTED_AHRP
REAL_AGENT_DEMAND_VALIDATED
REAL_WORLD_ADOPTION_VALIDATED
```

「真实 Orchestrator Agent 会不会主动查询 AHRP」不能由当前实现回答；
该问题保留给独立运行的模型型 Agent 试验（DESIGN_ONLY，见
`experiments/ahrp-external-agent-adoption-trial-v0.1/DESIGN_ONLY.md`）。

## 3. Components (executable role implementations)

四个程序化组件（注册于 `config/agent-roster.json`，每项含
`agent_id / agent_version / capabilities / boundary`）。这些组件不是
「真实 Agent」：

1. **programmatic orchestrator component** `did:example:orchestrator-core`
   — 接收任务、选择执行组件、记录委派理由的确定性程序。
2. **programmatic worker component** `did:example:worker-alpha` (Coding)
   — 实际写代码并编译；边界：无依赖解析。
3. **programmatic worker component** `did:example:worker-beta` (Research)
   — 实际生成研究文件；边界：禁止外部数据源。
4. **programmatic worker component** `did:example:worker-gamma` (Review)
   — 实际生成审查记录；边界：无安全审计。

```text
These executable components are not evidence of autonomous,
model-based, or externally operated agent adoption.
这些可执行组件不能证明自主智能体、模型型智能体或外部智能体采用了 AHRP。
```

## 4. Phase 1 — NO_AHRP_MODE baseline

Flow: `Task -> Orchestrator component -> select worker -> execute -> record`.

Recorded per task: `task_id, candidate_agents, selected_agent,
selection_reason, result`.

Prohibited in this phase: any read of AHRP History, Experience Events, or
Verifications. Enforcement: the runner passes a `ForbiddenHistoryStore`
whose `query_events` raises `AhrpAccessForbidden`; baseline records carry
no AHRP fields (checked by tests and by `verify_trial.py`).

## 5. Phase 2 — AHRP_ASSISTED_MODE (configured path)

The AHRP-assisted execution path is CONFIGURED by the trial code; queries
are therefore configured behavior, not voluntary agent behavior.

Flow: `Task -> Orchestrator component -> Query AHRP -> read history ->
decide whether to change selection -> execute`.

Recorded per task: `task_id, before_query_decision, ahrp_query,
history_used, after_query_decision, decision_changed`.

Decision policy (documented, deterministic):

1. `before_query_decision` = static type routing.
2. For every candidate component, one real `HistoryStore.query_events`
   call on the exact `(identity_ref, agent_version, task_type)` triple.
3. Veto a candidate when its history contains a failure-class event whose
   `failure_category` matches the task's declared risk requirement:
   - `CAPABILITY_LIMIT` -> reason `CAPABILITY_LIMIT_HISTORY`
   - `POLICY_RESTRICTION` -> reason `POLICY_RESTRICTION_HISTORY`
4. On any `Q_*` error envelope: FAIL CLOSED — keep the before-query
   decision, stop querying (`QUERY_ERROR`).
5. `NO_RECORD` never changes a decision.
6. All candidates vetoed -> route to `MANUAL_REVIEW`.

Only structured summary fields of the query envelope are consumed; free
text is never read (DATA != INSTRUCTION).

## 6. Scale

20 tasks: 10 No-AHRP + 10 AHRP-assisted. Task types: coding, research,
review (plus one data_processing task probing NO_RECORD). Deliberately
small.

## 7. Seed history

6 records generated by `config/generate_seed_history.py` (deterministic):

- worker-alpha: CODING FAILURE CAPABILITY_LIMIT (dependency resolution) +
  CODING SUCCESS;
- worker-beta: RESEARCH FAILURE POLICY_RESTRICTION (external sources) +
  RESEARCH SUCCESS;
- worker-gamma: VERIFICATION FAILURE CAPABILITY_LIMIT (security review) +
  VERIFICATION SUCCESS.

Each seed has a real evidence body with a real SHA-256 and a
`SYSTEM_BENCHMARK` verification — NOT `INDEPENDENT_AGENT`;
`REAL_INDEPENDENT_VERIFICATION=false` is preserved.

## 8. Metrics and their interpretation

Recorded data:

```text
TASK_COUNT=20
AHRP_QUERY_COUNT=12
PROGRAMMATIC_DECISION_CHANGED_COUNT=3
RESOLVABLE_HISTORY_REFERENCE_COUNT=16
```

Mandatory interpretation constraints:

> AHRP_QUERY_COUNT is produced by the configured AHRP-assisted execution
> path. It is not evidence that an autonomous agent voluntarily chose to
> query AHRP.
>
> AHRP_QUERY_COUNT 来自预先配置的 AHRP 辅助执行路径，不能证明自主智能体
> 自愿选择查询 AHRP。

Decision changes may only be described as
`PROGRAMMATIC_ROUTING_CHANGE_OBSERVATION`，不得称为 ADOPTION_SIGNAL、
AGENT_DEMAND_SIGNAL 或 REAL_AGENT_BEHAVIOR。

Query cost (observational): latency, tokens estimate (`len(json)//4`),
call count.

Prohibited metrics: agent score, agent ranking, trust score, reliability
score, and any "AHRP improved performance" statement.

## 9. Generated records and verification

Executed delegations in Phase 2 produce real Experience Events +
Verifications (verifier_class `SYSTEM_BENCHMARK`, full-event binding),
validated by the AHRP Validator at creation and again by `verify_trial.py`.

## 10. Judgement

本试验没有「成功/失败」采用判定。结果恒为：

```text
TRIAL_RESULT=INCONCLUSIVE
INTEGRATION_MECHANISM_DEMONSTRATED=(queries>0 AND routing changes>0)
```

集成机制得到演示不等于采用得到验证。阶段间执行结果差异仅为观察记录，
任务组合为触发历史消费而设计，不构成任何成功率比较。

## 11. Freeze guarantee

AHRP Schema, Validator, Query Engine, Spec and Constitution are NOT
modified by this trial. `run_trial.py` records `origin/main:AHRP` tree
hash into `analysis/summary.json`; `verify_trial.py` re-checks every
produced record against the unmodified AHRP Validator.
